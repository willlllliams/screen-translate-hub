# 账号、设备与共享

本文规定用户能直接感知的账号、设备接入、服务开放和屏幕共享规则，以及安全与隐私的基本要求。

## 1 一个主人，多台设备

一套部署服务一个主人。主人登录后可以接入自己的多台设备，包括多台装有桌面端的 Windows 或 macOS 电脑，以及用来观看的手机和电脑浏览器。

首版不提供多人独立空间、成员角色和访客观看分享。

## 2 登录

平台自带登录，不依赖其他账号系统。主人使用账号和密码登录，并可以额外开启验证器二步验证，即基于时间的一次性密码（Time-based One-Time Password，TOTP）。

主人忘记密码或丢失验证器时，由部署者在服务器上用命令行重置。开启二步验证时，平台同时生成一组一次性恢复码，主人丢失验证器时可以用恢复码登录。

## 3 电脑接入

### 3.1 三个依次设置的开关

桌面端与后台的关系由三个开关分别控制。后一个开关以前一个为前提：开启联网需要先配对，开放服务需要先开启联网。

| 开关 | 打开后的效果 |
| --- | --- |
| 配对 | 这台电脑成为主人的设备 |
| 开启联网 | 桌面端主动连接后台，可以参与跨设备的工作流 |
| 开放服务 | 后台和其他设备可以调用这台电脑上被逐项选中的本机服务 |

配对使用一次性配对码：主人在网页端生成配对码，在桌面端输入。配对码只能使用一次，桌面端不需要知道主人的密码。

桌面端主动连接后台，主人不需要为每台电脑单独开放公网端口。

### 3.2 可开放的本机服务

桌面端配对并开启联网后，可以把以下本机服务开放给后台。每项服务由用户在桌面端上单独勾选，未勾选的服务只供本机使用。

| 服务 | 接收 | 产生 |
| --- | --- | --- |
| OCR | 图片 | 文字与包围框 |
| 翻译 | 某种语言的文字 | 目标语言的译文 |
| 语言模型 | 文字与对话上下文 | 回答或译文 |
| 视觉模型 | 图片与问题 | 回答 |
| 自定义 HTTP 请求 | 工作流给出的地址与数据 | 从这台电脑发出请求，返回响应 |
| 卡片显示 | OCR 结果和对应图片 | 在这台电脑上显示浮卡 |
| AI 提示 | AI 的评价或回答 | 在这台电脑的鼠标旁显示 |

语言模型和视觉模型服务让其他设备使用这台电脑上的模型，例如用带显卡的台式机运行本地视觉模型，供没有显卡的笔记本上的图片问 AI 调用。

开放自定义 HTTP 请求后，后台可以让这台电脑向工作流指定的任意地址发出请求，包括这台电脑所在局域网内的地址。

表中每一行是一类服务。同一类的不同引擎各是一项服务，分别勾选、分别开放。本机服务以本机进程运行，电脑上不需要安装 Docker，见 [服务拆分](06-services.md)。

### 3.3 每台电脑只管理自己

每台电脑只管理自己的本机服务。本机服务使用的引擎、凭据和开放范围，都在这台电脑的桌面端上配置。

网页端编辑工作流时，绑定到其他电脑的节点只能选用那台电脑已经开放的服务，并填写该服务允许的调用参数。绑定在"本机"的节点，由发起运行的电脑解析为它自己的服务，不需要开放。为了让网页端也能为"本机"列出可选的服务，每台电脑把本机服务的描述登记到后台；这份目录只含描述，后台和其他设备不能据此调用这些服务。

后台不能绕过桌面端上的开放设置调用未开放的服务，只有一个例外：运行协调器放在后台时，可以为这台电脑自己发起的运行，调用它绑定在"本机"的服务。

### 3.4 撤销电脑

主人可以在网页端撤销某台电脑，撤销立即生效：

- 这台电脑与后台断开，它的来源下线；
- 运行协调器放在后台、由这台电脑发起的运行立即停止，不等断连的宽限期；
- 它开放的服务不再可用，其他工作流中绑定到这些服务的节点按失败处理；
- 这台电脑上的桌面端可以继续独立使用，要再次接入后台，需要重新配对。

## 4 屏幕共享

### 4.1 由源电脑主动开启

屏幕采集和共享必须在源电脑上主动开启。网页端无法远程开启某台电脑的屏幕采集。

### 4.2 处理服务与屏幕共享分开授权

开放某项处理服务，只允许其他设备把数据发给这项服务处理。例如，电脑 A 开放了 OCR 和本地翻译，没有开启屏幕共享：其他设备可以把图片发给 A 做 OCR、把文字发给 A 翻译，但无法取得 A 的屏幕画面。

### 4.3 来源

一路来源对应一次正在进行的持续屏幕运行，它同时满足两个条件：

- 运行所在的电脑开启了屏幕共享；
- 运行的工作流包含网页显示节点。

屏幕共享开关决定观看端能否取得这台电脑的画面和译文，网页显示节点决定运行向观看端发送哪些内容，两者缺一不可。开启了共享但没有满足条件的运行时，这台电脑不出现在来源列表中。

屏幕共享开关只管观看。工作流把 OCR、归一化或其他处理节点绑定在后台或其他电脑上时，即使没有开启共享，画面和文字也会按工作流发去处理。这由工作流的执行位置决定，与共享开关无关。

首版每台电脑同时只有一个持续屏幕运行（[产品需求](01-product.md) 4.2），一台电脑因此最多提供一路来源，来源列表用设备名和采集范围标明它。

屏幕共享开关随时生效，不属于运行开始时固定的配置。关闭共享后，后台立即停止向观看端转发这台电脑的画面和译文，丢弃相应的显示快照，相关来源从来源列表中消失，正在观看的观看端显示该来源已下线。运行本身继续进行，本机覆盖层不受影响。

## 5 观看

主人在手机或电脑浏览器上登录后，来源列表中显示当前所有来源，来源的构成见 4.3。主人从中选择一路观看，同一时刻只显示一路。

同一路来源可以被多个设备同时观看。所有观看端共用这一路的翻译目标语言和翻译结果，显示设置由每个观看端各自保存。

首版不区分会话权限：主人在任何设备上登录，得到的都是完整权限的会话。网页端列出当前登录的会话，主人可以逐个注销，例如手机丢失时注销手机上的会话。注销立即生效：这个会话已经打开的页面随即断开，不能继续观看或操作。修改密码时，其他会话同样立即失效。只读的观看会话与访客分享一起留到以后。

## 6 跨设备调用

不同设备之间的数据传递和服务调用，统一经过后台转发。观看端也通过后台取得画面和译文。

一次运行只调用它的工作流中明确连接的服务。某项服务即使已经开放，没有连接到当前工作流中，这次运行也不会调用它。

## 7 安全与隐私

- 桌面端、观看端与后台之间的连接一律使用 TLS 加密；
- 后台转发的画面和显示快照只放在内存里，运行结束或来源下线后即丢弃，不写入磁盘。用户主动发给 AI 的画面属于 AI 对话，按 [产品需求](01-product.md) 第 8 节保存到历史记录；
- 平台自身不收集、不上报任何使用数据。用户配置的外部服务，按各自的条款处理收到的数据；
- 桌面端本机保存的历史截图加密存放，密钥交给系统的凭据存储（Windows 的数据保护接口 Data Protection API，简称 DPAPI；macOS 的钥匙串），同一台电脑上的其他账户读不到；
- 后台首版不对历史截图做应用层加密：密钥只能和数据放在同一台服务器上，拿到服务器的人照样能解开。部署说明要求服务器开启磁盘加密。
