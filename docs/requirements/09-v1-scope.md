# 第一版范围

本文划定第一版（Windows 单机版）做什么、不做什么，并补充讨论中新增的需求。01 至 08 的需求保持不变，作为长期目标；第一版对其中某项的取舍，以本文为准。实现方式见规格说明 [第一版实现](../spec/18-v1-implementation.md) 和 [AI 助手](../spec/17-assistant.md)。

## 1 目标

第一版在一台 Windows 11 电脑上独立运行，不部署 Docker 后台：

- 单次截图翻译和持续屏幕翻译可用，译文画在屏幕原位，竞速、段落复用和译文缓存按 [OCR 与竞速翻译](03-ocr-and-translation-race.md) 和 [运行与生命周期](04-run-lifecycle.md) 实现；
- 同一局域网里的手机和电脑可以用浏览器观看持续屏幕的翻译结果；
- AI 助手的整条链路可以跑通：门控决定何时叫醒 AI，AI 通过平台提供的工具看屏幕、在屏幕上画标注、在悬浮卡片里说话；
- 整体按服务拆分，每个服务是独立进程，接口按规格说明定义，以后可以逐个替换实现、搬到别的设备上。

## 3 补充的需求

### 3.1 显示方式可以切换

持续屏幕和单次截图的结果各有两种显示方式，用户在设置中切换，切换只影响绘制，不重新识别和翻译：

| 显示方式 | 效果 | 默认 |
| --- | --- | --- |
| 原位底板 | 每个段落在原文位置盖一块半透明深色圆角底板，上面绘制译文；段落之外的画面不处理 | 默认 |
| 整屏压暗 | 整个采集范围压暗，译文以正常亮度绘制在原文位置，即 01 第 5.2 节的效果 | |

单次截图的结果另有两种呈现位置：

| 呈现位置 | 效果 | 默认 |
| --- | --- | --- |
| 画在原位 | 译文直接画在屏幕上被框选的位置，按 Esc、点击别处或再次截图时消失 | 默认 |
| 截图浮卡 | 01 第 4.1 节的可拖动浮卡，原图和译文分层 | |

原位底板的不透明度、整屏压暗的亮度都可以调节。显示方式和设置由每个显示端各自保存（01 第 5.5 节）。

### 3.2 已经是目标语言的段落不翻译

段落的语言与目标语言相同时，这一段不送去翻译，也不显示译文和错误标记，结束状态记为完整结果，来历记为"无需翻译"。比较时语言子标签必须相同；两边都写了文字子标签时，文字子标签也必须相同。例如 `zh`、`zh-Hans` 与目标语言 `zh-Hans` 视为相同；`zh-Hant` 与 `zh-Hans` 不同，繁体译为简体照常翻译。

没有这一条时，目标语言为中文的用户，屏幕上的每一段中文都会被送去"中译中"，不支持这个方向的翻译源会让每一段中文都显示错误标记，AI 翻译源还会产生费用。

同样不翻译的还有**没有可译的词**的段落：不含字母（数字、时间、日期、符号），或者只有单个拉丁、希腊、西里尔字母（工具栏上的 B、I、X、H1 这类图标被识别成的文字）。汉字、假名、谚文的单字仍然翻译。结束状态和显示同上，来历记为 `no_words`。持续翻译整个屏幕时，任务栏的时钟、窗口的关闭按钮、编辑器的工具栏都会被识别出来，不加这一条会在它们上面盖满无意义的底板。

译文与原文只差空白时（文件名、代码、产品名），显示端不画这一段的底板，以免盖住原文却没有提供新信息。

### 3.3 翻译源

第一版提供以下翻译源，都实现同一个翻译接口（规格说明 [服务接口](../spec/09-service-interfaces.md) 第 13 节）：

| 翻译源 | 说明 |
| --- | --- |
| Claude Code 无头模式 | 调用本机已登录的 Claude Code（`claude -p`），模型可选，测试默认用最便宜的模型。只用于开发测试和委托方自用 |
| 兼容 OpenAI 的接口 | 填写地址、模型和密钥，覆盖大多数 AI 服务商、Ollama、llama-server |
| Anthropic 接口 | 填写密钥和模型 |
| Bergamot 本地翻译 | 离线、免费，模型按需下载，复用 Firefox 的模型 |
| 模拟翻译源 | 按脚本给出译文、延迟和失败，用于测试竞速 |

默认的翻译源是 Claude Code（首选）加 Bergamot：Bergamot 的机翻先出现，随后被质量更好的 AI 译文替换，与 william 旧版的演示一致；没有 Claude Code 时 Bergamot 单独工作。

### 3.4 局域网观看

- 观看服务在本机监听一个局域网端口，同一网络中的浏览器访问这个地址观看；
- 访问需要一个访问口令，桌面端在设置和托盘菜单中显示访问地址和口令，口令可以重新生成；
- 观看端的行为按 01 第 5.4 节：显示正在处理的批次画面，译文按位置叠加，显示设置各自保存；
- 屏幕共享开关照常生效（05 第 4.3 节）：关闭时不向观看服务发送画面。
- 托盘菜单可以复制带访问码的链接，用手机打开即可，不用手动输入访问码；
- 观看页除"画面加译文"外，还可以改成"列表"：按阅读顺序列出译文，适合在手机上看整块桌面；
- Windows 防火墙：观看服务第一次在局域网上监听时，系统会询问是否允许 Node.js 接受网络连接，需要用户选择允许（专用网络即可），手机才能连上。设置里可以选择只监听本机，这时不会询问。

### 3.5 快捷键

默认快捷键，用户都可以修改：

| 功能 | 默认键位 |
| --- | --- |
| 截图翻译（框选） | Alt+Shift+S |
| 开始或暂停持续屏幕 | Alt+Shift+C |
| 显示或隐藏覆盖层 | Alt+Shift+H |
| 切换覆盖层的交互模式 | Alt+Shift+I |
| 唤起 AI 助手 / 让 AI 卡片获得键盘焦点 | Alt+Shift+A |

william 旧版只按 Shift+Alt 就开始框选。只有修饰键的组合要用低级键盘钩子监听，留到后续版本作为可选项。

## 4 AI 助手

### 4.1 定位

AI 助手是一个常驻的 AI 悬浮卡片，和用户一起看屏幕。用户给它一个任务或问题，例如"帮我看这份报表有没有对不上的数"、"这篇论文里的 xx 是什么意思"，之后大部分时间不需要打字：平台按心跳截取屏幕，由门控判断什么时候值得叫醒 AI，AI 看过屏幕后在悬浮卡片里回答，或者直接在屏幕上画框、箭头和气泡来指示。

### 4.2 边界

- AI 不控制鼠标和键盘，不替用户点击和输入。平台给 AI 的工具中不包含任何输入类操作，从结构上保证这一点；
- AI 不读写文件、不执行命令；
- AI 看到的屏幕画面同样不包含平台自己的窗口和鼠标指针；
- 用户随时可以暂停或关闭 AI 助手，暂停期间不截屏、不调用 AI。

### 4.3 组成

| 组成 | 作用 |
| --- | --- |
| AI 悬浮卡片 | 常驻、可拖动、不抢焦点；显示 AI 的回答和当前状态；按快捷键获得键盘焦点后输入问题 |
| 心跳截图 | 按设定的间隔截取屏幕，复用持续屏幕的采集和变化检测 |
| 门控 | 决定是否叫醒 AI：规则门控默认启用；另留模型门控的接口，可以接入 jev 这类快速决策模型 |
| AI 大脑 | 第一版用 pi 框架，模型可配置；平台能力以工具形式提供给它 |
| 屏幕标注 | AI 画在屏幕上的框、箭头、气泡、高亮，跟随窗口移动，可以设定自动消失时间 |

各部分的接口见规格说明 [AI 助手](../spec/17-assistant.md)。
