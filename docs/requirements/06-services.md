# 服务拆分

本文规定平台怎样拆分成服务（Service）、每类服务在哪里运行、以什么形式部署。拆分的目的是尽可能提高兼容性：每一部分都能单独替换，也能单独搬到能运行它的设备上，某一个平台或某一个引擎的限制只影响它自己。

## 1 拆分原则

平台按以下原则拆分：

1. 每个工作流节点由一个服务执行，一个服务只做一件事。
2. 同一类能力的不同引擎各是一个服务。例如两个 OCR 引擎是两个服务，各自声明支持的语言、平台和显卡，可以分别部署在不同位置。
3. 同一类服务使用同一套接口。换引擎或换执行位置时，工作流只改节点绑定的服务，结构不变。
4. 服务之间只通过接口通信，不共享内存和文件。
5. 共用同一份运行状态的职责不拆开，由运行协调器统一承担，理由见第 4 节。

兼容性的收益直接来自前三条。某个引擎只能在某个平台上运行时，它的限制只落在自己的服务上。例如一个只提供 Linux 版本、需要 NVIDIA 显卡的 OCR 引擎，可以部署在后台容器里，macOS 桌面端的工作流把 OCR 节点绑定到后台，就能调用它。反过来，只在 Windows 上提供的系统 OCR 也可以作为一项本机服务开放出来，供其他设备的工作流调用。

## 2 服务的分类

| 类别 | 包含的服务 | 运行位置 | 部署形式 |
| --- | --- | --- | --- |
| 系统集成服务 | 屏幕采集（含变化检测）、框选截图、取词、本机覆盖层、浮卡与对话面板、鼠标旁提示、快捷键与输入事件、窗口跟踪 | 桌面端 | 本机进程；Windows 和 macOS 各一份实现 |
| 处理服务 | OCR、归一化、翻译、AI 对话、视觉 AI、自定义 HTTP 请求 | 本机、后台或其他电脑 | 容器镜像或本机进程，两种形式来自同一份实现 |
| 运行协调器 | 每次运行一个 | 本机或后台 | 本机进程或容器镜像 |
| 后台平台服务 | 账号与认证、设备连接与中转、服务注册、观看分发、网页前端、工作流与配置存储、历史记录存储 | 后台 | 容器镜像 |

## 3 各类服务

### 3.1 系统集成服务

系统集成服务（System Integration Service）直接调用操作系统的桌面接口：截取屏幕、在其他应用上方绘制窗口、读取其他应用中选中的文字、监听全局快捷键。

这类服务不能放进容器：

- Docker 在 macOS 上用一台 Linux 虚拟机运行容器；在 Windows 上，Docker Desktop 也是在 WSL 2 的 Linux 内核中运行 Linux 容器。容器里的 Linux 程序调用不到 Windows 和 macOS 的桌面接口；
- Windows 原生容器在 Windows 专业版和企业版上，按微软的许可只能用于测试和开发。

因此系统集成服务以本机进程运行，每个平台各实现一份，对外接口相同。工作流和运行协调器只通过接口使用它们，不区分平台。两个平台各自依赖的系统能力见 [桌面平台](07-desktop-platforms.md)。

屏幕采集服务同时完成变化检测：每张截图先在采集服务内与参照画面比对，只有发生了变化的画面才交出去。变化检测必须在源电脑上执行，放在别处就要把每一张截图都传出去；在源电脑上单独做成一个服务，每张截图也要从采集进程整张复制到变化检测进程。4K 画面每张约 33 MB，截屏间隔 0.5 秒时每秒要复制约 66 MB，而画面静止时这些截图最终全部被丢弃。并入采集服务后，截图不离开采集进程。比对和变化图的算法写成与平台无关的库，两个平台的采集服务共用，规则见规格说明 [变化检测](../spec/05-change-detection.md)。

### 3.2 处理服务

处理服务（Processing Service）处理数据，不依赖桌面接口，同一份实现提供两种部署形式：

- 容器镜像：部署在后台，或者部署者自己的其他机器上；
- 本机进程：随桌面端安装，在用户电脑上运行。用户电脑不需要安装 Docker，本机进程可以直接使用电脑的显卡。

桌面端独立使用时，工作流用到的处理服务都以本机进程运行。

调用操作系统自带引擎的服务是例外，例如 Windows 的系统 OCR。它只在对应的系统上以本机进程运行，没有容器镜像，在登记时声明支持的平台，见第 5 节。

在 Mac 上，需要显卡的处理服务只能以本机进程运行。Docker Desktop 的容器显卡直通只在 Windows 的 WSL 2 后端提供，Mac 上的容器用不了 Mac 的显卡。后台部署在 Mac 上时也是如此：需要显卡的处理服务以本机进程运行在这台 Mac 上，再注册到后台。

归一化不保存状态，可以绑定在任何位置，默认与运行协调器放在一起。

### 3.3 后台平台服务

后台平台服务负责账号与认证、设备连接与中转、服务注册、观看分发、网页前端、工作流与配置存储和历史记录存储，每个服务单独打包为容器镜像。

家庭部署时另有一个透传中转服务，部署在有公网地址的服务器上，只转发加密后的数据，见 [产品需求](01-product.md) 2.2。

平台提供一份编排文件，默认一次启动全部后台平台服务和随后台提供的处理服务。部署者也可以只启动其中一部分，或者把某个处理服务放到另一台机器上运行，再注册到后台。

容器镜像同时提供 linux/amd64 和 linux/arm64 两种架构。Apple 芯片的 Mac 是 arm64 主机，只提供 amd64 镜像时，容器要靠仿真运行，计算密集的任务会明显变慢。个别引擎只发布了一种架构，例如 PaddlePaddle 在 PyPI 上的 Linux 安装包只有 x86_64 版本，它的服务就只在对应架构的机器上提供，并在注册时声明（见第 5 节）。

编排文件只使用 Compose 规范里的功能，不依赖 Docker Desktop。Docker Desktop 只对个人使用、教育、非商业开源项目和小企业免费，小企业指员工少于 250 人并且年收入低于 1000 万美元，其他商业使用需要付费订阅；Docker Engine 等开源组件不受这项许可约束。部署者因此可以在 Linux 服务器上直接使用 Docker Engine，在 Mac 上也可以选用其他兼容 Compose 的容器工具。

## 4 运行协调器

运行协调器（Run Coordinator）执行一次运行。它按工作流调用各个服务，管理运行、批次、段落竞速和请求的生命周期，完成复用判定、译文缓存和竞速，并把结果汇总后发给所有显示端。每次运行有一个运行协调器，位于本机或后台，由用户在工作流中选择，见 [工作流](02-workflow.md) 4.2。

这些职责不再拆开，因为它们依赖同一份运行状态，而且必须同时生效：

- 暂停或停止时，要一次关闭当前批次、各段落竞速和相关请求的生命周期，见 [运行与生命周期](04-run-lifecycle.md) 第 6 节；
- 生命周期关闭后，晚到的结果要统一丢弃，判断依据是候选是否属于当前运行和当前批次，见 [OCR 与竞速翻译](03-ocr-and-translation-race.md) 5.2；
- 复用判定、译文缓存和竞速要按同一份竞速结果判断，例如只有完整结果才能进入译文缓存。

拆成多个服务以后，每一条都要靠服务之间同步状态才能成立：一个服务已经关闭了生命周期，另一个服务还可能把晚到的结果写进画面。

## 5 注册与描述

每个服务启动后向后台的服务注册登记。桌面端独立使用时，由桌面端在本机维护一份服务清单，本机服务向它登记。其他电脑上的服务只有开放之后才能被调用。没有开放的本机服务只把描述登记到后台，作为这台电脑的本机服务目录，供网页端为"本机"位置列出可选的服务，不能被调用。规则见 [账号、设备与共享](05-accounts-devices-sharing.md) 3.2、3.3。

每个服务注册时声明以下信息：

| 信息 | 用途 |
| --- | --- |
| 服务类别与引擎 | 节点编辑器按类别列出可选的服务 |
| 接收和产生的数据 | 检查连线两端的数据是否匹配 |
| 支持的语言 | 确定 OCR 识别语言和语言对的可选范围 |
| 支持的平台、处理器架构与显卡加速方式 | 说明服务能在哪些设备上运行、是否使用显卡、用哪种方式加速 |
| 并发上限与请求速率上限的默认值 | 运行协调器据此给请求排队，用户可以调低，见 [运行与生命周期](04-run-lifecycle.md) 第 10 节 |
| 接口版本 | 检查服务与工作流、运行协调器是否兼容，见第 6 节 |

服务之间的通信协议和描述格式在 spec 阶段确定。

## 6 接口版本

每个服务声明自己实现的接口版本，服务可以单独升级。

工作流校验时，平台检查每个节点所绑定服务的接口版本。不兼容的服务在校验时报错，工作流不能进入可运行状态，见 [运行与生命周期](04-run-lifecycle.md) 第 1 节。

运行期间某个服务升级重启，正在进行的调用按失败结束。下一次调用这个服务之前，运行协调器重新检查它的接口版本；不兼容时，这个节点按失败结束，平台不自动改用其他服务。

## 7 故障隔离

一个服务崩溃或重启，只影响绑定到它的节点：这些节点按失败或超时结束，规则见 [工作流](02-workflow.md) 4.4，平台不自动改用其他服务，其他服务继续运行。

系统集成服务是例外。它们都运行在桌面端主程序的进程里，其中之一崩溃时，主程序整体退出，本机正在进行的运行随之结束。放在同一个进程里，是因为 macOS 按应用归属屏幕录制和辅助功能权限，而且平台自己的窗口要在同一个应用里才能一并排除在截屏之外，理由见规格说明 [桌面端](../spec/12-desktop.md) 1.1。

运行协调器本身不可用时，它负责的整次运行无法继续，例如运行协调器放在后台而后台断连，见 [运行与生命周期](04-run-lifecycle.md) 8.1。
