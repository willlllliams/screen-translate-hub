# 术语表

本表列出需求文档中反复出现的术语。各文档首次使用某个术语时会再交代一次全称，之后固定使用表中的称呼。

## 处理相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 光学字符识别（OCR） | Optical Character Recognition | 从图片中识别文字的处理步骤。平台中由一个 OCR 节点完成，用户为每个节点选择一个 OCR 引擎 |
| 包围框（bbox） | Bounding Box | OCR 给出的文字所在区域。每个文字块对应一个包围框 |
| 归一化 | Normalization | 把不同 OCR 引擎的输出整理成统一格式：统一坐标、整理阅读顺序、合并行与段落，生成带唯一标识的翻译单元 |
| 段落 | Paragraph | 归一化后的翻译单元。一个段落可以由多个原始文字块合并而成，并保留这些原始包围框 |
| 翻译源 | Translation Source | 产生译文候选的一路来源，例如某个 AI 模型、某个服务器翻译接口或某个本地翻译引擎。同一个 AI 的流式输出和完整输出分别算作两个翻译源 |
| 流式源 | Streaming Source | 边生成边返回译文的翻译源。每次返回的是当前累计的译文，并带有递增的版本号；输出正常结束时给出带完成标记的版本 |
| 完整源 | Complete Source | 一次性返回整段完整译文的翻译源 |
| 候选 | Candidate | 某个翻译源针对某个段落返回的一份译文，由翻译源、版本和完成标记三项描述 |
| 竞速 | Race | 同一段落的多个翻译源并发执行，平台按用户设定的优先级和版本规则决定当前显示哪份候选 |
| 优先级 | Priority | 用户给所有启用的翻译源排出的先后顺序，用于决定候选之间能否互相替换 |
| 首选源 | Preferred Source | 启用的翻译源中优先级最高的一个。竞速的最终结果只能来自首选源，其他源的译文只在首选源给出译文之前临时显示。首选源对某一段失败、没有给出任何译文时，这一段显示错误提示；首选源整体不可用时，段落保留其他源的临时译文 |
| 版本 | Version | 同一个翻译源对同一段落先后给出的候选的序号。流式源每输出一次累计译文，版本加一 |
| 完成标记 | Completion Flag | 候选上的标记，表示该翻译源对该段落的输出已经正常结束。完整源的候选都带完成标记，流式源只有最后一个版本带 |
| 语言对 | Language Pair | 翻译的源语言与目标语言。参加同一场竞速的翻译源共用竞速节点上的语言对 |

## 工作流相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 工作流 | Workflow | 由输入、处理、输出节点及其连线组成的处理流程。用户可以创建多条工作流 |
| 节点 | Node | 工作流中的一个步骤，例如屏幕输入、OCR、翻译、AI、分支、显示输出 |
| 入口 | Entry | 用户触发工作流的方式，包括单次截图、持续屏幕、划词、图片问 AI |
| 模板 | Template | 平台为每个入口提供的默认工作流，用户可以修改或另建 |
| 执行位置 | Execution Location | 节点实际运行的设备，例如某台电脑或 Docker 后台 |
| 操作面板 | Operation Panel | 日常使用的界面：选择入口、采集范围、工作流和参数后直接运行 |
| 节点编辑器 | Node Editor | 修改工作流结构的画布界面 |
| 服务 | Service | 可以独立部署、独立调用的功能单元。每个工作流节点由一个服务执行，同一类能力的不同引擎各是一个服务 |
| 系统集成服务 | System Integration Service | 依赖操作系统桌面接口、只能在桌面端以本机进程运行的服务，例如屏幕采集（含变化检测）、本机覆盖层、取词。Windows 和 macOS 各有一份实现，对外接口相同 |
| 处理服务 | Processing Service | 处理数据、不依赖桌面接口的服务，例如 OCR、归一化、翻译、AI。同一份实现既能打包成容器镜像，也能作为本机进程运行；调用操作系统自带引擎的服务，例如 Windows 的系统 OCR，只在对应系统上以本机进程运行 |
| 运行协调器 | Run Coordinator | 执行一次运行的服务。它调用各个服务，管理生命周期，完成复用判定、译文缓存和竞速，并把结果分发给显示端。每次运行有一个，位于本机或后台 |

## 运行相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 运行 | Run | 一个入口触发的一次完整执行。单次截图、划词和图片问 AI 每触发一次是一次运行；持续屏幕从点击开始到停止是一次运行，中间可以暂停和恢复，暂停后恢复仍属于原来的运行 |
| 触发方式 | Capture Trigger | 决定持续屏幕何时截屏的方式。首版为按用户设定间隔的定时触发，后续加入鼠标点击、键盘操作和快捷键触发 |
| 批次 | Batch | 一次截图或一张确认发生变化的屏幕画面，以及围绕它进行的 OCR、归一化和翻译。持续屏幕的批次只对变化的区域重新识别和翻译 |
| 待处理位 | Pending Slot | 持续屏幕运行中暂存下一张待处理截图的位置，最多保存一张，新截图会替换旧截图 |
| 参照画面 | Reference Frame | 变化检测判断新截图是否变化时用来比对的画面，取最近一张被接受的画面 |
| 变化图 | Change Map | 变化检测比对新旧两张画面得出的结果，标明哪些区域发生了变化、哪些区域整体平移以及平移了多少 |
| 段落复用 | Paragraph Reuse | 持续屏幕的新批次直接沿用上一批次中原地未变或整体平移的段落，连同它的识别结果和译文，不再重新识别和翻译 |
| 译文缓存 | Translation Cache | 一次运行内按竞速节点和原文保存的译文，只保存首选源给出的完整译文。新批次中原文相同的段落直接使用，不再竞速 |
| 节点超时 | Node Timeout | 单个节点一次调用允许的最长时间 |
| 批次总时限 | Batch Deadline | 一个批次从开始处理到结束允许的最长时间 |
| 显示快照 | Display Snapshot | 某一时刻一路显示结果的完整内容：画面、包围框位置和选中的译文。各显示端按自己的显示设置绘制它 |
| 显示设置 | Display Settings | 亮度、字号、图层显隐等只影响绘制效果的设置。每个显示端各自保存，调整时只影响该显示端，不重新触发 OCR 或翻译 |
| 本机覆盖层 | Local Overlay | 本机持续翻译覆盖层的简称。桌面端盖在实时屏幕之上的透明图层，不绘制截图，只绘制暗化层、译文和整体提示 |

## 设备相关

| 术语 | 英文 | 含义 |
| --- | --- | --- |
| 主人 | Owner | 一套部署唯一的管理账号，管理自己的多台设备 |
| 桌面端 | Desktop Client | 安装在 Windows 或 macOS 电脑上的客户端，负责截图、划词、持续屏幕采集和本机显示。首版同时提供 Windows 版和 macOS 版 |
| 来源 | Source | 可以被观看的一次持续屏幕运行：运行所在的电脑开启了屏幕共享，工作流包含网页显示节点 |
| 观看端 | Viewer | 登录后观看某一路来源的浏览器，包括手机和电脑 |
| 后台 | Backend | 以容器部署的一组服务，负责账号、设备连接、跨设备中转和服务器侧处理，默认用一份编排文件一次启动 |
| 透传中转 | Pass-through Relay | 家庭部署时运行在有公网地址的服务器上的中转服务。家里的后台主动连上它，它只转发加密后的数据，看不到画面和译文 |
