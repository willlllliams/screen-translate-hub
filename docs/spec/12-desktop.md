# 桌面端

对应需求：[产品需求](../requirements/01-product.md) 第 2.3、2.4、4、5 节，[桌面平台](../requirements/07-desktop-platforms.md) 全文，[服务拆分](../requirements/06-services.md) 第 3.1、7 节。

本文规定桌面端的进程划分、主程序的结构、本机存储，以及系统集成服务在 Windows 和 macOS 上的实现方式。技术栈见 [技术选型](15-tech-selection.md) 第 3 节。

## 1 进程划分

桌面端由一个主程序进程和若干按需启动的本机服务进程组成：

| 进程 | 内容 | 可执行文件 |
| --- | --- | --- |
| 主程序 | 桌面端主程序的全部职责（[架构](01-architecture.md) 2.1）；八项系统集成服务；全部界面窗口 | Tauri 应用 |
| 运行协调器 | 本机执行的运行 | 与后台容器相同的 Rust 程序 |
| 归一化 | 无状态的归一化服务 | 同上 |
| OCR | 每个 OCR 引擎一个进程；Windows 的系统 OCR 只在 Windows 上提供（需求 06 第 3.2 节） | 同上 |
| 翻译 | 每个翻译引擎一个进程，例如 Bergamot | 同上；Bergamot 的 MPL 代码只编进这个进程（[技术选型](15-tech-selection.md) 7.1） |
| llama-server | 运行下载的 GGUF 格式模型；GGUF 是 llama.cpp 使用的模型文件格式。只监听 `127.0.0.1` 的随机端口，凭随机 API 密钥访问（[安全](11-security.md) 第 5 节） | llama.cpp 的官方程序 |
| AI 适配、自定义 HTTP 请求 | 用户配置了相应服务时启动 | 与后台容器相同的 Rust 程序 |

### 1.1 系统集成服务在主程序进程内

八项系统集成服务都在主程序进程内运行，依据有三条：

1. 系统权限的归属最确定。macOS 按"责任代码"归属屏幕录制和辅助功能权限，判定是启发式的；有开发者实测，辅助功能权限不会传给包内的普通辅助程序（[技术选型](15-tech-selection.md) 3.3）。权限的申请者和使用者是同一个进程，用户在系统设置中看到的也就是这个应用；
2. 排除截屏最简单。macOS 的 ScreenCaptureKit 按应用排除窗口；覆盖层、浮卡和提示都由主程序进程创建，排除主程序这一个应用，就排除了平台自己的全部窗口；
3. 界面窗口必须在主程序进程中：覆盖层、浮卡、对话面板和鼠标旁提示都是 Tauri 的窗口。

代价是故障隔离变粗：一项系统集成服务崩溃，整个主程序随之退出。这对用户的影响与单独崩溃差别不大：主程序是本机服务与后台之间唯一的出入口（[架构](01-architecture.md) 2.1），它不在，本机的运行本来就无法继续。主程序崩溃后，由系统的登录项机制在下次登录时重新启动，用户也可以手动打开；本机服务进程失去与主程序的连接后自行退出。

为降低崩溃的可能，系统集成服务尽量用 Rust 编写，只有 macOS 上必须调用 Swift 和 Objective-C 接口的部分用 Swift，划分见 [技术选型](15-tech-selection.md) 3.3；调用系统接口中可能阻塞的部分，例如取词，放在专用线程上，并设置超时（第 3.5、4.5 节）。

需求 06 第 7 节已把这一点写为故障隔离的例外：系统集成服务共享主程序进程，其中之一崩溃时，主程序整体退出，本机正在进行的运行随之结束。

### 1.2 本机服务进程的生命周期

- 主程序在第一次需要某项本机服务时启动它，例如运行协调器为一次运行调用 `agent.Acquire`（[服务接口](09-service-interfaces.md) 第 3 节）。启动参数包括本机端点路径；本机会话令牌经标准输入传入（[安全](11-security.md) 第 5 节）。llama-server 另外按安全第 5 节的规定启动：随机端口，API 密钥经只有当前用户能读的文件传入；
- 服务启动后连上主程序登记（[服务接口](09-service-interfaces.md) 第 3 节）；
- 加载了大模型的服务，例如 OCR、翻译、llama-server，没有任何 `Acquire` 流占用它、并且这样持续一段时间（默认值待定）后，主程序请它退出，释放内存。本机进程之间直接连接，主程序看不到调用是否频繁，所以按占用判断空闲：运行期间，运行协调器一直占用它用到的服务（[服务协议](08-service-protocol.md) 8.3）；
- 服务进程崩溃时，主程序按 [服务协议](08-service-protocol.md) 第 10 节的退避间隔重新启动它，服务重新登记后，主程序在占用它的 `Acquire` 流上推送新的描述和端点，运行协调器据此恢复调用；连续 5 次在启动后 30 秒内崩溃，不再自动重启，在设置页标明这项服务不可用及其日志位置。

## 2 主程序

### 2.1 界面

| 窗口 | 内容 | 平时是否显示 |
| --- | --- | --- |
| 托盘或菜单栏图标 | 功能入口菜单、运行状态 | 始终 |
| 主窗口 | 操作面板、历史面板、运行详情、设置、模型管理、节点编辑器 | 从图标菜单打开 |
| 本机覆盖层 | 持续屏幕运行时一个；首版每台电脑同时只有一个持续屏幕运行（需求 01 第 4.2 节） | 运行时 |
| 浮卡、对话面板 | 截图浮卡、划词浮卡、桌面对话面板 | 运行时 |
| 鼠标旁提示 | 鼠标附近问 AI 的回答 | 运行时 |
| 框选界面 | 截图和图片问 AI 的框选 | 框选时 |

所有窗口的界面都用同一套 React 前端编写。节点编辑器与网页端是同一份代码（需求 02 第 1 节）；覆盖层、截图浮卡与网页观看端共用 [显示与排版](07-display.md) 第 5 节的排版代码。

浮卡为了不抢焦点而不能被激活。"让最近一张浮卡获得键盘焦点"的快捷键临时允许这张浮卡被激活，用户在其中输入追问；追问发出或按 Esc 后，浮卡恢复为不可激活，焦点回到原来的窗口。屏幕阅读器用户用同一个快捷键操作浮卡，浮卡的内容同时写入主窗口的历史面板，主窗口按平台的无障碍规范实现（需求 01 第 5.3 节）。截图浮卡上被截断的译文，也在历史面板中查看全文。

桌面对话面板由用户从菜单主动打开，是可以激活的普通窗口，用户点击即可输入，平台窗口的其他规则照常适用：排除在采集之外，显示在覆盖层之上（3.3、4.4）。

### 2.2 入口与快捷键

快捷键与功能的对应关系保存在主程序的设置中（需求 01 第 4.5 节）。Windows 上的默认键位遵守微软的键盘设计指南：

- 不使用带 Win 键的组合，这类组合留给系统使用；
- 不使用 Ctrl+Alt 组合。指南写明，部分语言版本的 Windows 把 Ctrl+Alt 当作 AltGr 键处理，用来输入字符，这类快捷键会挡住这些键盘布局下的字符输入；
- 不使用 `@`、`$`、`{}`、`[]`、`\`、`~`、`|`、`^`、`'`、`<`、`>` 这些在不同键盘布局下按法不同的字符。

快捷键按虚拟键码加修饰键保存，不按字符保存：同一个键在不同键盘布局下输入的字符不同，虚拟键码不变。macOS 上的默认键位避开系统已经占用的组合，例如 Command 加空格（聚焦搜索）。具体键位在原型阶段确定。

用户按下某个入口的快捷键，或者从菜单选择入口时，主程序按这台电脑上该入口用法绑定的工作流（[工作流定义](03-workflow.md) 5.1），确定运行协调器的位置，调用它的 `coordinator.Run` 发起运行。

### 2.3 后台链路

主程序配对后，按用户的"开启联网"开关（需求 05 第 3.1 节）维持与后台的连接：握手按 [服务协议](08-service-protocol.md) 第 3 节，断开后按服务协议第 10 节的退避间隔重连。握手被拒绝时按原因码处理：`REVOKED` 表示这台电脑已被撤销，主程序停止重连，清除本机的配对信息，提示用户重新配对；`PROTOCOL_INCOMPATIBLE` 表示协议主版本不兼容，主程序停止重连，提示升级较旧的一方，按独立使用的方式工作（第 6 节）。连接建立后，主程序依次：

1. 向服务注册登记这台电脑开放的服务和本机服务目录；
2. 通过 `viewer.SetSharing` 报告屏幕共享开关；
3. 上传尚未上传的历史记录，补做离线时记下的删除和保留标记变化，订阅 `history.WatchChanges`；
4. 缓存本机入口绑定的后台工作流（第 6 节）。

连着后台期间，主程序每保存一条历史记录就上传一条，上传失败的留到下次连接时补传（需求 01 第 8 节）。主程序依赖的平台接口，例如 `registry`、`viewer`、`history`、`config`，主版本与后台不兼容时，主程序同样提示升级较旧的一方，按独立使用的方式工作。

### 2.4 模型管理

安装包只带自带引擎的最小模型，其他模型在模型管理中按需下载（需求 01 第 2.3 节）：

- 模型目录是一个 JSON 清单，随每个桌面端版本发布在项目的发布页上，列出每个模型的名称、用途、许可、体积、下载地址和 SHA-256 校验值；
- 下载源默认是项目的发布页，用户可以改为镜像地址。从镜像下载时，清单本身仍从发布页获取，校验值以发布页的清单为准，镜像只提供文件；
- 下载完成后核对 SHA-256，不一致时删除文件并提示；
- 模型管理的说明中显示每个模型的许可，以及需要写明的附加条件，例如 manga-ocr 使用了 Manga109-s 数据集（[技术选型](15-tech-selection.md) 6.2）；
- 下载的模型加入所属引擎的服务：例如韩文、阿拉伯文识别模型加入自带 OCR 服务的识别语言，服务随即重新登记，描述中的语言列表随之扩充（[服务协议](08-service-protocol.md) 第 12 节）。识别语言为自动时只用默认模型，要识别这些语言，用户在 OCR 节点上选定语言（技术选型 6.2）。

### 2.5 升级

桌面端在每次启动时和每天检查一次更新，用户确认后才安装；持续屏幕正在运行时，不自动重启（需求 01 第 2.4 节）。更新信息从项目的发布页获取，安装包的签名由操作系统在安装时验证。

### 2.6 出站代理

桌面端访问外部 AI、翻译服务和模型下载地址时，按以下规则选择代理（需求 01 第 2.5 节）：

- 默认跟随系统的代理设置：Windows 读取系统的代理配置，macOS 读取系统偏好设置中的网络代理；
- 用户可以在设置中改为单独的 HTTP 或 SOCKS5 代理；
- 每个外部服务可以覆盖上面的设置，单独指定走代理或直连，例如境外服务走代理，本机和局域网中的服务直连。

主程序把生效的代理设置交给需要访问外部网络的本机服务进程和功能，即 AI 适配服务、自定义 HTTP 请求服务、模型下载、检查更新和下载安装包。翻译服务不访问外部网络，外部翻译接口经自定义 HTTP 接口节点接入（[服务接口](09-service-interfaces.md) 第 15 节）。本机进程之间、主程序与后台之间的连接不受这些设置影响：后台连接按用户填写的后台地址直接连接，后台地址需要经代理访问时，同样在设置中为它指定。

## 3 Windows

### 3.1 基本设置

- 应用清单声明每显示器 DPI 感知 V2。窗口坐标、`DWMWA_EXTENDED_FRAME_BOUNDS` 和采集坐标因此都是物理像素（[数据模型](02-data-model.md) 1.4）；
- 界面运行在 WebView2 中。Evergreen 运行时预装在所有 Windows 11 设备上，安装程序在极少数缺失的情况下联网安装它；
- 本机数据存放在 `%LOCALAPPDATA%\screen-translate-hub\`；
- 本机端点使用命名管道，访问控制列表只允许当前用户（[安全](11-security.md) 第 5 节）。

### 3.2 屏幕采集

- 用 `IGraphicsCaptureItemInterop` 的 `CreateForMonitor` 或 `CreateForWindow` 建立采集项，不经系统选择器（需求 07 第 2 节）；
- 帧池使用 `B8G8R8A8UIntNormalized` 格式。`IsCursorCaptureEnabled` 设为假，采集不含鼠标指针；
- 先调用 `GraphicsCaptureAccess.RequestAccessAsync(Borderless)`，再把 `IsBorderRequired` 设为假（需求 07 第 5.1 节）。微软文档只说明了打包应用的流程，非打包程序的结果没有官方说明；原型阶段实测，不可行时用"带外部位置的打包"给主程序取得包标识（[技术选型](15-tech-selection.md) 第 13 节）；
- 定时触发：帧到达时只保留最新的一帧，每隔截屏间隔 $\Delta$ 取出当前最新的一帧交给变化检测。Windows 11 24H2 起，`MinUpdateInterval` 设为 $\Delta$，让系统少产生用不到的帧；
- 读取像素：把帧纹理复制到暂存纹理，映射后按行复制到连续的缓冲区，去掉行尾填充，得到 [数据模型](02-data-model.md) 第 2 节的画面格式；
- Windows 11 24H2 起，`DirtyRegions` 可以作为变化检测的提示，前提见 [变化检测](05-change-detection.md) 2.4。它的语义没有官方说明，原型阶段确认后再启用。

窗口采集时，窗口外框取 `DWMWA_EXTENDED_FRAME_BOUNDS`，它不含 Windows 用于调整大小的不可见边框。采集帧与这个矩形的对应关系微软没有官方说明，原型阶段在 100%、125%、150% 缩放和混合缩放的多显示器上实测，确定采集几何中的 `origin_x`、`origin_y`。

### 3.3 窗口与覆盖层

平台自己的窗口按用途设置样式：

| 窗口 | 扩展样式 | 其他设置 |
| --- | --- | --- |
| 本机覆盖层 | `WS_EX_LAYERED`、`WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE`、`WS_EX_TOOLWINDOW` | 交互模式下去掉 `WS_EX_TRANSPARENT` |
| 浮卡 | `WS_EX_TOPMOST`、`WS_EX_NOACTIVATE`、`WS_EX_TOOLWINDOW` | 在 `WM_MOUSEACTIVATE` 中返回 `MA_NOACTIVATE`，可以拖动但不被激活。按"让最近一张浮卡获得键盘焦点"时，临时去掉 `WS_EX_NOACTIVATE` 并激活它，追问发出或按 Esc 后恢复（2.1） |
| 桌面对话面板 | `WS_EX_TOPMOST` | 普通的可激活窗口，出现在任务栏中 |
| 鼠标旁提示 | `WS_EX_TOPMOST`、`WS_EX_LAYERED`、`WS_EX_TRANSPARENT`、`WS_EX_NOACTIVATE`、`WS_EX_TOOLWINDOW` | 不接收点击，点击穿透到下方的窗口 |
| 框选界面 | `WS_EX_TOOLWINDOW` | 覆盖全部显示器 |
| 主窗口 | 无 | 普通窗口 |

以上全部窗口，包括主窗口，都调用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，排除在一切屏幕采集之外（需求 01 第 5.6 节）。主窗口的历史面板显示着平台自己的译文，进入采集会被重新识别；macOS 按应用排除，主窗口本来就在排除之列（4.2），两个平台因此一致。这个设置只对顶层窗口有效，并依赖桌面窗口管理器的合成，这些窗口都满足。

浮卡、桌面对话面板和鼠标旁提示始终显示在覆盖层之上：三者都是置顶窗口，每次显示时用 `SetWindowPos(HWND_TOPMOST, …, SWP_NOACTIVATE)` 排到置顶窗口的最前；覆盖层重新排序时（3.4）不越过它们。否则采集整块显示器时，置顶的覆盖层会盖住浮卡，交互模式下浮卡上的按钮也点不到。

表中的样式按 [技术选型](15-tech-selection.md) 3.1 的规则设置：Tauri 提供了接口的，经它的接口设置；`WS_EX_TOOLWINDOW` 和 `WM_MOUSEACTIVATE` 的处理按技术选型 3.1 的例外办理，在原型阶段验证（技术选型第 13 节）。

鼠标旁提示不接收点击，也不能被激活。它显示期间，主程序用 `RegisterHotKey` 临时把 Esc 注册为全局快捷键，并安装低级鼠标钩子 `WH_MOUSE_LL` 监听鼠标按下：按下的位置不在提示之内时，提示消失。提示消失后立即注销两者。这段时间里前台程序收不到 Esc（[服务接口](09-service-interfaces.md) 第 9 节）。以管理员身份运行的程序在前台时，低级钩子收不到输入（需求 07 第 4.1 节），全局快捷键不受影响，用户仍可以按 Esc 关闭提示。

Tauri 的窗口库显示不可聚焦的窗口时会把它激活，修复尚未合并（[技术选型](15-tech-selection.md) 3.1）。这些窗口因此由主程序取得窗口句柄后，用 `ShowWindow(SW_SHOWNOACTIVATE)` 显示。

覆盖层的层级按采集范围而定：

- 整块显示器和固定区域：置顶窗口（`WS_EX_TOPMOST`），盖在一切普通窗口和无边框全屏的游戏之上（需求 07 第 2.2 节）；
- 某个窗口：不置顶，用 `SetWindowPos` 把覆盖层排在目标窗口的正上方（需求 07 第 2.1 节）。目标窗口被激活、层级变化时，重新排一次。被其他窗口挡住的部分，由系统的窗口层级自然遮住。

### 3.4 窗口跟踪

用 `SetWinEventHook` 以进程外方式订阅以下事件。回调中处理目标窗口的事件；跟随活动窗口时，`EVENT_SYSTEM_FOREGROUND` 对所有窗口处理，跳过平台自己的窗口，前台是平台自己的窗口时，采集范围保持原来的窗口（[服务接口](09-service-interfaces.md) 第 10 节）：

| 事件 | 用途 |
| --- | --- |
| `EVENT_OBJECT_LOCATIONCHANGE` | 窗口移动或改变大小，覆盖层随之移动（需求 01 第 5.2 节） |
| `EVENT_SYSTEM_MINIMIZESTART`、`EVENT_SYSTEM_MINIMIZEEND` | 隐藏和恢复整个覆盖层，暗化层也在内（[显示与排版](07-display.md) 2.1） |
| `EVENT_SYSTEM_FOREGROUND` | 重新排列覆盖层的层级；"跟随活动窗口"的采集范围据此切换目标 |
| `EVENT_OBJECT_DESTROY` | 目标窗口关闭。采集范围是固定的窗口时，采集会话报告 `TARGET_CLOSED`，运行停止；跟随活动窗口时不报告，等下一个前台窗口（需求 04 第 8.3 节） |

### 3.5 取词

取词在专用的多线程单元（MTA）线程上进行，这个线程不拥有任何窗口（需求 07 第 4.1 节；微软的 UI 自动化线程规则）：

1. 判断前台程序的完整性级别。高于主程序时，直接返回 `ELEVATED_TARGET`，不再尝试：用户界面特权隔离会让后面的步骤全部失败；
2. 用 UI 自动化取得焦点元素，经文本模式取选区文字。调用前把事务超时调低（默认值待定，系统默认为 20 秒），目标程序无响应时，这一步按超时结束；
3. 取不到选区时，退而模拟 Ctrl+C：
   1. 记下当前剪贴板的内容和序号；
   2. 用 `SendInput` 发送 Ctrl+C；
   3. 等待剪贴板序号变化，最多等一个短时限（默认值待定）；
   4. 读取文字；
   5. 恢复原来的剪贴板内容。恢复时写入的数据附带 `ExcludeClipboardContentFromMonitorProcessing` 格式，这次恢复本身不进入剪贴板历史，也不同步到其他设备。

第 3 步的代价写在需求 07 第 4.1 节：目标程序复制出的那一份会进入剪贴板历史，平台无法给它加排除格式，因为它是目标程序写入的。

### 3.6 签名与安装

- 安装程序由 Tauri 的打包工具生成，使用 OV 代码签名证书签名（需求 07 第 8.1 节）；
- 安装包中的每个可执行文件和动态库都要签名，包括 ONNX Runtime、本机服务程序和 llama-server。Windows 11 的智能应用控制会拦截没有签名、也没有信誉的二进制文件；
- 主程序注册为登录时启动，用户可以在设置中关闭。

## 4 macOS

### 4.1 基本设置

- 应用的 `Info.plist` 设置 `LSUIElement` 为真，启动时把激活策略设为 accessory，不显示 Dock 图标（需求 07 第 3 节）。最低系统版本设为 15.0；
- 本机数据存放在 `~/Library/Application Support/` 下以包标识命名的目录中；
- 本机端点使用 Unix 域套接字，放在当前用户的临时目录（`$TMPDIR`）下权限为 0700 的子目录中，路径不超过 100 字节（[服务接口](09-service-interfaces.md) 第 3 节）。

### 4.2 屏幕采集

- 持续屏幕用 `SCStream`。内容过滤器按采集范围选择：整块显示器和固定区域用 `SCContentFilter(display:excludingApplications:exceptingWindows:)`，排除的应用就是主程序本身；某个窗口用只含这个窗口的过滤器；
- 流配置：`showsCursor` 设为假；像素格式为 BGRA；颜色空间为 sRGB；输出尺寸取采集范围的像素尺寸，即显示器、区域或窗口外框的点数乘以显示器的缩放比例，区域用 `sourceRect` 指定；`minimumFrameInterval` 设为截屏间隔 $\Delta$。这样每个点对应的像素数等于显示器的缩放比例，与采集几何的 `scale` 一致（[数据模型](02-data-model.md) 1.4）；
- 帧状态为 `idle` 时，显示内容没有变化，系统不产生新画面，变化检测不需要比对；帧附带的 `dirtyRects` 按 [变化检测](05-change-detection.md) 2.4 的条件使用，它的单位和原点在原型阶段确认；
- 单张截图和图片输入用 `SCScreenshotManager`（macOS 14 起），内容过滤器和流配置与持续屏幕相同：排除本应用，`showsCursor` 设为假，鼠标指针和平台自己的窗口都不进入画面（需求 01 第 5.6 节）；
- 流因用户在菜单栏结束共享而停止时，系统调用 `stream(_:didStopWithError:)`，错误码为 `userStopped`；采集会话据此报告 `USER_STOPPED`，运行转为暂停（需求 04 第 8.3 节）。

macOS 15 起，直接采集屏幕的应用会被系统定期要求用户再次确认（需求 07 第 4.3 节），桌面端在首次采集前的说明中告诉用户这个提示从哪里来。

### 4.3 系统权限

需求 07 第 4.2 节列出的四项权限，桌面端这样处理：

| 权限 | 何时申请 | 没有授权时 |
| --- | --- | --- |
| 屏幕与系统录音 | 第一次使用截图、持续屏幕或图片问 AI 之前，先说明用途，再触发系统的授权请求 | 这几项功能显示需要的权限和打开设置的入口，其余功能照常使用 |
| 辅助功能 | 第一次使用划词之前 | 划词浮卡说明原因（[服务接口](09-service-interfaces.md) 第 6 节的 `PERMISSION_MISSING`） |
| 输入监控 | 后续版本使用按键触发截屏时 | 只能使用定时触发 |
| 本地网络 | 第一次向局域网中的地址发起连接时，由系统自动询问：局域网中的后台、局域网里的 AI 服务、自定义 HTTP 请求的目标 | 这些连接都失败。连接后台、AI 适配服务和自定义 HTTP 请求服务的失败提示都说明原因，并引导用户在系统设置中打开 |

屏幕录制权限授予后，要重启应用才能开始采集（需求 07 第 4.2 节）。主程序检测到权限从未授权变为已授权时，提示用户重启，并提供一键重启。

### 4.4 窗口与覆盖层

覆盖层、浮卡和鼠标旁提示都是非激活面板，经 tauri-nspanel 设置（[技术选型](15-tech-selection.md) 3.1）；桌面对话面板是普通窗口，可以成为接收键盘输入的窗口，用户点击即可输入（2.1）。覆盖层的设置取苹果技术支持在开发者论坛确认、在 macOS 26 上测试通过的组合：

| 设置 | 取值 |
| --- | --- |
| 窗口样式 | `nonactivatingPanel` |
| 窗口层级 | `.screenSaver` |
| `collectionBehavior` | `.canJoinAllSpaces`、`.canJoinAllApplications`、`.fullScreenAuxiliary`、`.stationary` |
| 其他 | `isFloatingPanel` 为真，`hidesOnDeactivate` 为假，用 `orderFrontRegardless()` 显示 |
| 鼠标 | 覆盖层和提示显式设置 `ignoresMouseEvents` 为真；交互模式下设为假 |
| 浮卡、对话面板和提示的层级 | 高于覆盖层的 `.screenSaver`，取 `.screenSaver` 的值加一；`collectionBehavior` 与覆盖层相同，所以也能进入其他应用的全屏空间 |

`ignoresMouseEvents` 必须显式设置：没有设置时透明区域能否穿透点击，苹果当前的文档没有说明。

macOS 没有把窗口排在别的应用窗口正上方的官方方式，窗口采集时覆盖层留在上层，按遮挡裁掉译文（需求 07 第 2.1 节）：

1. 用 `CGWindowListCopyWindowInfo` 的 `optionOnScreenAboveWindow` 取得排在目标窗口之上的窗口及其外框，只保留其他应用的可见窗口：`kCGWindowOwnerPID` 不是主程序、`kCGWindowAlpha` 大于 0。覆盖层自己处在屏幕保护程序层级，外框与目标窗口相同，不排除它，减去之后就什么也不剩；
2. 从覆盖层的显示区域中减去这些外框；
3. 被减去的区域中既不绘制译文，也不绘制暗化层，挡在前面的窗口保持原样（需求 07 第 2.1 节）。

目标窗口不在屏幕上时，例如最小化，覆盖层整个隐藏，还原后重新显示（[显示与排版](07-display.md) 2.1）。

跟随活动窗口时，主程序订阅 `NSWorkspace` 的 `didActivateApplicationNotification`。某个应用被激活后，从 `CGWindowListCopyWindowInfo` 中取这个应用最靠前、`kCGWindowLayer` 为 0 的窗口，作为新的目标窗口。被激活的是桌面端自己时不切换。这两个接口都不需要权限（需求 07 第 2 节）。

鼠标旁提示不接收点击，也不能被激活。它显示期间，主程序用 `RegisterEventHotKey` 临时把 Esc 注册为全局快捷键，并用 `NSEvent.addGlobalMonitorForEvents` 监听鼠标按下：按下的位置不在提示之内时，提示消失。提示消失后立即注销两者。苹果对这个接口的说明只对键盘相关事件的监听要求辅助功能权限，鼠标按下不在此列，所以这个做法不增加权限；全局监听收不到发给本应用的事件，点击提示本身不会让它消失。

macOS 没有不需要权限的窗口移动通知，窗口跟踪按固定间隔（默认值待定）读取 `CGWindowListCopyWindowInfo`，取得目标窗口的外框、是否在屏幕上，以及排在它之上的窗口。外框取 `kCGWindowBounds`，单位是点。

### 4.5 取词

1. 检查辅助功能权限（`AXIsProcessTrustedWithOptions`）。没有授权时返回 `PERMISSION_MISSING`，浮卡说明需要哪项权限并引导用户打开设置（需求 07 第 4.2 节）；
2. 取系统级的焦点元素，读取 `kAXSelectedTextAttribute`。调用前用 `AXUIElementSetMessagingTimeout` 设置超时（默认值待定）；
3. 取不到时，退而模拟 Cmd+C，再读剪贴板，最后恢复原来的内容。读取剪贴板会触发 macOS 的剪贴板隐私提醒，用户选择"始终拒绝"后这条退路失效；桌面端在设置中说明这一点。

Chromium 系浏览器和 Electron 应用默认不暴露网页内容的无障碍信息（需求 07 第 4.2 节）。让它们开启无障碍模式的具体做法只有第三方资料，原型阶段确认。

### 4.6 签名与公证

- 应用以 Developer ID 签名，开启强化运行时，带安全时间戳，提交 Apple 公证（需求 07 第 8.2 节）；
- 本机服务程序和 llama-server 放在 `.app` 包内，用同一个开发者身份签名。它们只做计算，不需要屏幕录制等系统权限；
- 始终使用同一个签名身份，用户此前给的系统权限才能延续到新版本。

## 5 本机存储

| 内容 | 存放方式 |
| --- | --- |
| 设置、入口绑定、本机工作流，以及入口绑定的后台工作流的缓存副本 | SQLite 数据库 `desktop.db` |
| 历史记录 | 与后台相同的条目结构（[后台平台服务](10-backend.md) 8.1）；条目中的文字内容（原文、译文、对话）和图片文件都按 [安全](11-security.md) 7.3 加密 |
| 外部服务凭据 | 加密存放，规则同历史记录 |
| 运行详情 | 每次运行一个文件，按时间滚动删除 |
| 模型 | 模型管理下载的文件，按引擎分目录 |
| 设备私钥 | Windows 的 TPM，或 DPAPI 保护的文件；macOS 的安全隔区（[安全](11-security.md) 3.2） |

本机历史记录的容量上限由用户设置，达到上限时从最旧的记录开始清理，标记为保留的不清理。容量清理只删除本机的副本；用户删除、手动清理或改变保留标记，才同步到后台（需求 01 第 8 节，2.3）。

## 6 桌面端独立使用

以下任一情况下，桌面端独立工作（需求 01 第 2.3 节）：

- 没有配对；
- 关闭了"开启联网"；
- 握手因协议主版本不兼容被拒绝，或者连上后发现主程序依赖的平台接口主版本不兼容，这期间提示升级较旧的一方（需求 01 第 2.4 节）；
- 这台电脑已被撤销，握手以 `REVOKED` 被拒绝，提示用户重新配对（[服务协议](08-service-protocol.md) 第 3 节）。

没有服务器的部署者使用的离线版，就是前两种情况（需求 01 第 2.2 节）。独立工作时：

- 工作流只从本机存储读取，绑定只能解析到 `local`。入口绑定的是后台的工作流时，使用 2.3 节缓存在 `desktop.db` 中的副本，只读，节点全部绑定在本机的照常运行；缓存副本与后台的工作流不一致时，以重新连上后台时取得的后台版本为准；
- 运行协调器、处理服务都在本机启动；
- 网页显示和网页对话面板节点不输出（[工作流定义](03-workflow.md) 3.4）；
- 历史记录保存在本机，重新连上后台后再上传。
