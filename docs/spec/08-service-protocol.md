# 服务协议

对应需求：[服务拆分](../requirements/06-services.md) 第 5、6 节，[账号、设备与共享](../requirements/05-accounts-devices-sharing.md) 第 3、6 节，[运行与生命周期](../requirements/04-run-lifecycle.md) 第 4、6、8 节。

本文定义平台全部进程之间使用的通信协议：传输方式、帧格式、握手与认证、多路复用的流、流量控制、时限、状态码、寻址与路由、有状态的会话、连接保活，以及服务登记的描述格式。各服务的具体方法见 09 服务接口。选择自定义协议的理由见 [技术选型](15-tech-selection.md) 第 4 节。

## 1 设计要点

协议要同时满足以下要求：

- 两端对等：一条连接的任何一端都能发起调用。桌面端主动连上后台以后，后台通过这条连接调用电脑上开放的服务（[架构](01-architecture.md) 5.2）；
- 多路复用：一条连接上同时进行多个调用，大画面的传输不阻塞小的控制消息；
- 四种调用形态：一问一答、服务端连续回复、客户端连续发送、双方连续收发。翻译源的累计译文、显示事件、采集会话分别用到后三种；
- 时限和取消随调用传递（需求 04 第 4、6 节）；
- 流量控制：接收方处理不过来时，发送方停止发送；
- 同一套帧格式用于三种连接：本机进程之间、设备与后台之间、浏览器与后台之间。

## 2 连接与传输

### 2.1 三种连接

| 连接 | 传输 | 发起方 |
| --- | --- | --- |
| 网络连接 | TLS 上的 WebSocket（RFC 6455），子协议名 `sth.v1`，每个 WebSocket 二进制消息承载一个帧 | 桌面端主程序、浏览器、部署在其他机器上的处理服务 |
| 后台内部连接 | 编排网络内的 WebSocket，帧格式同上 | 后台的各个服务，连向设备连接与中转 |
| 本机连接 | Windows 命名管道或 macOS 的 Unix 域套接字，每个帧前加 4 字节的小端长度 | 同一台电脑上的进程 |

网络连接选 WebSocket，而不选裸 TCP：WebSocket 经过 Caddy 网关、frp 透传中转和常见的 HTTP 代理都没有障碍，浏览器也原生支持。

### 2.2 帧的编码

每个帧是一个 Protocol Buffers 消息 `Frame`，定义见第 13 节。一个帧的编码长度不超过 512 KiB。

业务消息（某个方法的请求或回复）同样用 Protocol Buffers 编码，放在 `Data` 帧的 `chunk` 字段中传输。一条业务消息超过 256 KiB 时，拆成多个 `Data` 帧依次发送，最后一个帧的 `end_of_message` 为真。拆分让不同调用的帧可以交替发送：一张 4K 画面拆成上百个帧，其间插入的控制消息不必等整张画面发完。

一条业务消息的总长度有上限：

- 本机连接：256 MiB。未压缩的 4K 画面约 33 MB，8K 画面约 133 MB；
- 网络连接和后台内部连接：32 MiB。经过网络的画面使用压缩编码（[数据模型](02-data-model.md) 第 2 节）。

## 3 握手与认证

连接建立后，在打开任何流之前，双方先完成握手。

网络连接的握手：

1. 服务端发送 `Challenge`，其中有一个 32 字节的随机数、后台标识和服务端支持的协议版本；
2. 客户端发送 `Hello`，其中有它选定的协议版本、身份类型和凭据；
3. 服务端验证凭据，回复 `HelloAck`。验证失败时回复 `HelloAck`（`accepted` 为假）并关闭连接，`code` 写明拒绝的原因。

`HelloAck` 的拒绝原因码决定客户端接下来怎么做：

| 原因码 | 含义 | 桌面端的处理 |
| --- | --- | --- |
| `REVOKED` | 这台电脑已被主人撤销 | 停止重连，清除本机的配对信息，提示用户重新配对（需求 05 第 3.4 节） |
| `PROTOCOL_INCOMPATIBLE` | 双方没有主版本相同的协议版本 | 停止重连，提示升级较旧的一方，按独立使用的方式工作（需求 01 第 2.4 节） |
| `INVALID_CREDENTIAL` | 签名或令牌不对 | 停止重连，提示用户检查配对 |
| `UNAVAILABLE` | 后台暂时无法验证，例如账号与认证服务正在重启 | 按第 10 节的退避间隔重连 |

浏览器收到 `INVALID_CREDENTIAL` 时，说明会话已经失效，页面转到登录页（[网页端](13-web.md) 第 2 节）。

`Hello` 中的凭据按身份类型而定：

| 身份类型 | 凭据 | 验证方式 |
| --- | --- | --- |
| `desktop` | 设备标识，以及对挑战随机数的签名 | [安全](11-security.md) 3.3 |
| `service` | 服务凭据 | [安全](11-security.md) 第 4 节 |
| `browser` | 无；WebSocket 升级请求中的会话 Cookie 已由网关转交 | [安全](11-security.md) 2.6，并检查 `Origin` 请求头 |

本机连接的握手：连接方发送 `Hello`，凭据是主程序启动时生成、经标准输入交给各个本机进程的本机会话令牌（[安全](11-security.md) 第 5 节）；被连接方核对后回复 `HelloAck`。

协议版本采用 [总览](00-overview.md) 3.6 的"主版本.次版本"规则，本文定义的是 1.0。客户端在服务端支持的版本中选择主版本相同、次版本最高的一个；没有可选的版本时，服务端拒绝握手。

## 4 流

### 4.1 流标识

一次调用在连接上表现为一条流，用 64 位整数标识。发起连接的一方打开的流使用奇数标识，接受连接的一方使用偶数标识，两端各自递增，不会冲突。

流标识只在一条连接上有意义。调用经设备连接与中转转发时，中转在两条连接上各用一个标识，自己记住两者的对应关系（第 8.2 节）。

### 4.2 打开流

调用方发送 `Open` 帧打开一条流：

| 字段 | 含义 |
| --- | --- |
| `stream` | 流标识 |
| `target` | 目标服务的地址，见 8.1 |
| `interface`、`interface_major`、`interface_minor` | 接口名和调用方要求的接口版本，例如 `ocr` 的 1.0 |
| `method` | 方法名 |
| `deadline_ms` | 剩余时长，毫秒；0 表示没有时限，见第 6 节 |
| `caller` | 调用方的身份，由中转和主程序填写，见 8.4 |
| `metadata` | 附加信息，例如运行标识、批次序号、请求标识，用于运行详情和日志 |

`Open` 之后，调用方紧接着就可以发送请求消息，不需要等待对方确认。目标不存在、方法不存在或接口版本不兼容时，被调用方回复 `Close`，状态码分别为 `unavailable`、`unimplemented`、`incompatible`。

### 4.3 消息

打开流以后，双方都可以发送业务消息。每个方法规定自己的调用形态：

| 形态 | 调用方发送 | 被调用方发送 | 例子 |
| --- | --- | --- | --- |
| 一问一答 | 一条请求 | 一条回复 | OCR 识别一组区域 |
| 服务端连续回复 | 一条请求 | 多条回复 | 翻译源逐步给出累计译文 |
| 客户端连续发送 | 多条消息 | 最多一条回复 | 运行协调器向覆盖层发送显示事件 |
| 双方连续收发 | 多条消息 | 多条消息 | 采集会话、浮卡与追问 |

同一条流上的消息按发送顺序到达。

### 4.4 结束

一方发完自己的全部消息后，发送 `HalfClose`，此后只接收、不再发送。

被调用方发送 `Close` 结束整条流，其中带有状态（第 7 节）。`Close` 之后双方都不再发送这条流的任何帧，收到的迟到帧直接丢弃。正常结束的流状态码为 `ok`。

### 4.5 取消

调用方发送 `Cancel` 请求取消一条流，并在其中写明原因，例如"批次结束""用户暂停"。被调用方收到后，尽快停止计算，回复 `Close`，状态码为 `cancelled`。

调用方发出 `Cancel` 后，不再处理这条流上到达的业务消息；运行协调器的有效候选规则同样会丢弃它们（[运行协调器](04-run-coordinator.md) 6.1）。取消是尽力而为的：被调用方可能已经把结果发出，也可能所调用的外部服务无法中途停止，这些情况都不影响正确性，只多消耗一些计算或费用。

## 5 流量控制

每条流的每个方向都有一个发送额度，单位是字节，按 `Data` 帧中 `chunk` 的长度计算：

1. 新打开的流，两个方向的初始额度都是 1 MiB；
2. 发送方发送一个 `Data` 帧，额度减去它的 `chunk` 长度。额度不足时停止发送这条流，其他流不受影响；
3. 接收方把收到的 `chunk` 放进这条流正在重组的消息。只要这条流上没有"已经重组完成、但业务代码还没有取走"的消息，接收方就立即发送 `Credit` 帧，把这些字节数加回对方的额度；有这样的消息时，等业务代码取走它，再补发此前扣住的额度。

第 3 条让超过 1 MiB 的消息也能完整送达：重组一条大消息的过程中，接收方不断补充额度，发送方不会停在半条消息上。设一条消息长 $L$ 字节，初始额度为 $w$。若接收方要等整条消息被业务代码取走才补额度，发送方发出 $w$ 字节后就停下，而 $L > w$ 时这条消息永远收不齐，双方互相等待。按第 3 条，额度在重组期间就补回，这个等待不会出现。

第 3 条同时提供背压：业务代码没有取走上一条消息时，额度不再补充，发送方最多再发出初始额度那么多字节就停下。每条流在接收方积压的数据因此不超过一条完整的消息加 1 MiB。手机上的观看端处理得慢，发送方随之停下；观看分发此时不排队积压事件，等额度恢复后直接发送最新的快照（[后台平台服务](10-backend.md) 5.3）。

额度是端到端的：经设备连接与中转转发的流，`Credit` 帧也原样转发，中转不自行发放额度。这样发送方的额度反映的是最终接收方的处理速度。

中转为了限制自己的内存占用，规定每条连接同时打开的流不超过 128 条。按初始额度计算，一条连接上在途的数据最多 $128 \times 1\ \text{MiB} = 128\ \text{MiB}$。

## 6 时限

`Open` 帧的 `deadline_ms` 是发出时的剩余时长（[总览](00-overview.md) 3.4）。时限的处理规则：

- 被调用方收到 `Open` 时，记下本地单调时钟的读数 $t_{\mathrm{recv}}$，本地时限为 $t_{\mathrm{recv}} + \mathtt{deadline\_ms}$。到时尚未结束时，停止计算，回复 `Close`，状态码为 `deadline_exceeded`；
- 中转和主程序转发 `Open` 时，减去这个帧在自己这里停留的时间，再转发出去。减去后不大于 0 时，不再转发，直接回复 `Close`，状态码为 `deadline_exceeded`。`deadline_ms` 为 0 表示没有时限，所以转发方必须做这个判断，不能把已经到期的调用变成不限时的调用；
- 调用方同时按自己的时限独立处理：到时就发送 `Cancel`，并按超时处理这次调用，不等被调用方的回复；
- 被调用方再调用其他服务时，下游调用的时限不得晚于自己的本地时限。

运行协调器发出请求时，`deadline_ms` 取 [运行协调器](04-run-coordinator.md) 7.4 中的 $t_{\mathrm{req}} - t_{\mathrm{send}}$。

## 7 状态码与失败类别

`Close` 帧中的状态由状态码、给人看的说明和可选的重试等待时间组成。说明文字不得包含画面、识别出的文字、译文和凭据（[安全](11-security.md) 7.4）。

| 状态码 | 含义 | 运行协调器的失败类别 |
| --- | --- | --- |
| `ok` | 正常结束 | — |
| `cancelled` | 调用方取消 | — |
| `deadline_exceeded` | 超过时限 | 单段失败 |
| `invalid_argument` | 请求内容不合法 | 单段失败 |
| `not_found` | 请求引用的对象不存在，例如会话已经结束 | 单段失败 |
| `engine_error` | 引擎处理这次请求时失败 | 单段失败 |
| `internal` | 服务内部错误 | 单段失败 |
| `unavailable` | 目标设备或服务不可达，或者连接中断 | 整体不可用 |
| `rate_limited` | 被限流；可以附带重试等待时间 | 整体不可用 |
| `quota_exceeded` | 达到费用上限 | 整体不可用 |
| `incompatible` | 接口版本不兼容 | 整体不可用 |
| `unimplemented` | 服务没有这个方法 | 整体不可用 |
| `permission_denied` | 开放控制拒绝了这次调用 | 整体不可用 |
| `unauthenticated` | 身份认证失败 | 不用于流；握手失败时使用 |

"失败类别"一列是 [运行协调器](04-run-coordinator.md) 6.3 的两类失败。划分的依据是失败是否与这一次请求的内容有关：前一组只与这次请求有关，换一段原文可能就成功；后一组与请求内容无关，换哪一段都一样会失败。

一条服务端连续回复的流，以 `ok` 结束、但流式输出的最后一个版本没有完成标记时，运行协调器按单段失败处理（需求 03 第 4.2 节"流式输出中断时，不会出现带完成标记的版本"）。

## 8 寻址与路由

### 8.1 地址

一个服务实例的地址由两部分组成：

| 字段 | 内容 |
| --- | --- |
| `device` | 设备标识。后台本身也是一台设备，安装时生成自己的标识 |
| `service` | 服务在这台设备上的登记名称，同一设备上唯一，例如 `ocr.ppocr-v6-small`、`translate.bergamot`、`agent` |

几个保留名称：

| 名称 | 所在 | 服务 |
| --- | --- | --- |
| `agent` | 每台电脑 | 桌面端主程序本身，以及它托管的系统集成服务 |
| `hub` | 后台 | 设备连接与中转 |
| `registry` | 后台 | 服务注册 |
| `auth` | 后台 | 账号与认证 |
| `viewer` | 后台 | 观看分发 |
| `config` | 后台 | 工作流与配置存储 |
| `history` | 后台 | 历史记录存储 |

### 8.2 中转的路由

设备连接与中转维护一张路由表：每台在线的电脑对应它的主程序连接；后台的每个服务对应它的服务连接。

中转收到 `Open` 时：

1. 按 `target.device` 和 `target.service` 找到目标连接。找不到时，回复 `Close`，状态码为 `unavailable`；
2. 在目标连接上分配一个新的流标识，记下两条流的对应关系；
3. 改写 `caller`（8.4）和 `deadline_ms`（第 6 节），转发 `Open`；
4. 此后双向原样转发这两条流上的 `Data`、`HalfClose`、`Close`、`Cancel`、`Credit` 帧。

中转不解码业务消息，只看帧头。一条连接断开时，中转对其上每条流的另一端发送 `Close`（状态码 `unavailable`），并向被调用方发送 `Cancel`。

### 8.3 桌面端主程序的路由

主程序在桌面端承担同样的转发角色：

- 本机进程调用其他设备上的服务：经主程序与后台的连接发出，主程序同样记录流的对应关系；
- 后台转来的调用：主程序先做开放检查（[安全](11-security.md) 第 6 节），通过后转给目标本机服务；目标是主程序自己托管的系统集成服务时，直接在进程内处理；
- 本机进程调用同一台电脑上的其他服务：不经过主程序，调用方直接连接目标服务的本机端点。运行协调器在运行期间先用 `agent.Acquire` 占用要调用的本机服务，主程序据此启动服务、返回端点，并在占用期间不按空闲回收它（09 服务接口 `agent` 接口，[桌面端](12-desktop.md) 1.2）。直连的调用不经过主程序，主程序看不到调用是否频繁，所以服务的启停只按占用判断。

### 8.4 调用方身份

`Open` 帧中的 `caller` 描述调用方的身份，由转发它的中转和主程序填写，发起方自己填写的值会被覆盖：

| 字段 | 内容 | 填写方 |
| --- | --- | --- |
| `kind` | 身份类型：电脑、后台服务、浏览器 | 中转，按这条连接的握手结果 |
| `device` | 电脑的设备标识；后台服务填后台的设备标识；浏览器为空 | 中转 |
| `service` | 发起调用的服务的登记名称；浏览器为空 | 后台服务由中转按握手身份填写；电脑上的本机进程由主程序填写 |
| `session` | 浏览器会话的标识；其他身份为空 | 中转 |

被调用方据此判断调用来自哪台设备、哪个服务、哪个浏览器会话，并按 [安全](11-security.md) 第 6 节做开放检查。设备无法冒充别的设备，因为 `kind`、`device` 和 `session` 只由中转按认证结果填写。

## 9 有状态的会话

有状态的交互，用一条长期的双方连续收发的流表示：流打开就是会话开始，流关闭就是会话结束。例如：

- 运行协调器与屏幕采集服务的采集会话：运行协调器发送"取批次""暂停""恢复"，屏幕采集服务回复批次画面和变化图，或者报告采集被外部中断；
- 运行协调器与浮卡的会话：运行协调器发送译文和 AI 回答，浮卡发回用户的追问，用户关闭浮卡时浮卡结束这条流。

会话与流同生共死，带来一个直接的好处：运行协调器崩溃或者断连时，流随连接一起关闭，屏幕采集服务随即停止采集，浮卡也知道运行已经结束，不会留下没有主人的会话。

## 10 保活与重连

连接两端每 15 秒没有收发任何帧时，发送一个 `Ping`，对方立即回复 `Pong`。连续 45 秒没有收到任何帧，判定连接已断开，按 8.2 的规则关闭其上的全部流。

桌面端主程序与后台的连接断开后，按退避间隔重新连接：第一次等 1 秒，之后每次加倍，最长 60 秒，每次另加 0 到 20% 的随机抖动，避免大量电脑在后台重启后同时重连。

一方准备关闭连接时，例如服务升级重启，先发送 `GoAway`，此后不再打开新的流，等已有的流结束或超时后再断开。

## 11 接口版本

每个服务为它实现的每个接口声明一个版本（需求 06 第 6 节）。版本检查发生在三个时刻：

1. 运行前检查时，对照服务清单中的登记信息；保存工作流时，编辑器对后台和其他电脑上的绑定先做一次同样的检查，提前提示不兼容（[工作流定义](03-workflow.md) 第 6 节）；
2. 每次打开流时，被调用方用 `Open` 中的版本与自己实现的版本比较，不兼容就回复 `incompatible`；
3. 服务重启后重新登记时，运行协调器检查新的版本（[运行协调器](04-run-coordinator.md) 第 12 节）。后台服务和电脑开放的服务重新登记，经服务注册的 `Watch` 通知；同一台电脑上的本机服务重新登记，由主程序在 `agent.Acquire` 的流上推送。

第 2 条让版本检查不依赖服务注册的信息是否及时：服务在两次登记之间升级了，调用也会立即发现不兼容。

## 12 服务的登记描述

每个服务启动后，向所在位置的服务清单登记：后台服务向服务注册登记，本机服务向主程序登记。登记的描述 `ServiceManifest` 包含需求 06 第 5 节列出的全部信息：

| 字段 | 内容 |
| --- | --- |
| `name` | 登记名称，同一设备上唯一 |
| `display_name` | 在节点编辑器中显示的名称 |
| `interfaces` | 实现的接口及版本，例如 `ocr` 1.0 |
| `engine` | 引擎的标识、名称和版本 |
| `languages` | 支持的语言：OCR 为识别语言；翻译为可用的源语言、目标语言，以及是否能自行判断源语言 |
| `platform` | 操作系统、处理器架构和可用的加速方式，例如 CPU、CUDA、Core ML |
| `limits` | 并发上限、请求速率上限和突发量的默认值，每次请求最多的段落数和字符数 |
| `streaming` | 翻译和 AI 服务是否支持流式输出 |
| `metering` | 计量方式：按调用次数、按字符或按词元，用于费用上限（需求 04 第 10 节） |

服务与登记处之间的连接断开时，登记自动失效；服务重连后重新登记。服务注册由此知道哪些服务此刻可用，不需要额外的心跳。描述有变化时，服务同样重新登记，例如 OCR 服务在用户下载了新的识别模型后，`languages` 随之扩充（[技术选型](15-tech-selection.md) 6.2）。

本机服务清单中，被用户勾选开放的服务，由主程序再登记到后台的服务注册（需求 05 第 3.2 节），地址的 `device` 是这台电脑的设备标识，可以被调用。其余本机服务只把描述作为这台电脑的本机服务目录登记上去，供网页端为"本机"位置列出可选的服务，不能被调用（需求 05 第 3.3 节）。开放范围变化、本机服务登记或注销时，主程序重新发送这两份列表。

## 13 帧的定义

```proto
syntax = "proto3";
package sth.wire.v1;

message Frame {
  oneof body {
    Challenge challenge = 1;
    Hello hello = 2;
    HelloAck hello_ack = 3;
    Open open = 4;
    Data data = 5;
    HalfClose half_close = 6;
    Close close = 7;
    Cancel cancel = 8;
    Credit credit = 9;
    Ping ping = 10;
    Pong pong = 11;
    GoAway go_away = 12;
  }
}

message Version {
  uint32 major = 1;
  uint32 minor = 2;
}

message Challenge {
  bytes nonce = 1;                 // 32 字节
  string backend_id = 2;
  repeated Version versions = 3;   // 服务端支持的协议版本
}

message Hello {
  Version version = 1;
  enum PeerKind {
    PEER_KIND_UNSPECIFIED = 0;
    DESKTOP = 1;
    SERVICE = 2;
    BROWSER = 3;
    LOCAL = 4;
  }
  PeerKind kind = 2;
  string peer_id = 3;              // 设备标识或服务名称
  oneof credential {
    bytes device_signature = 4;    // 对 Challenge.nonce 等内容的 ECDSA P-256 签名
    string service_token = 5;
    string local_token = 6;
  }
}

message HelloAck {
  bool accepted = 1;
  string reason = 2;                        // 写给人看的说明
  enum Code {
    CODE_UNSPECIFIED = 0;
    REVOKED = 1;
    PROTOCOL_INCOMPATIBLE = 2;
    INVALID_CREDENTIAL = 3;
    UNAVAILABLE = 4;
  }
  Code code = 3;                            // accepted 为假时填写
}

message Address {
  string device = 1;
  string service = 2;
}

message Open {
  uint64 stream = 1;
  Address target = 2;
  string interface = 3;
  uint32 interface_major = 4;
  uint32 interface_minor = 5;
  string method = 6;
  uint32 deadline_ms = 7;          // 剩余时长，0 表示没有时限
  Caller caller = 8;               // 由转发方填写
  map<string, string> metadata = 9;
}

message Caller {
  enum Kind { KIND_UNSPECIFIED = 0; DESKTOP = 1; SERVICE = 2; BROWSER = 3; }
  Kind kind = 1;
  string device = 2;
  string service = 3;
  string session = 4;
}

message Data {
  uint64 stream = 1;
  bytes chunk = 2;                 // 不超过 256 KiB
  bool end_of_message = 3;
}

message HalfClose {
  uint64 stream = 1;
}

message Close {
  uint64 stream = 1;
  Status status = 2;
}

message Cancel {
  uint64 stream = 1;
  string reason = 2;
}

message Credit {
  uint64 stream = 1;
  uint32 bytes = 2;
}

message Ping {
  uint64 nonce = 1;
}

message Pong {
  uint64 nonce = 1;
}

message GoAway {
  string reason = 1;
}

message Status {
  enum Code {
    OK = 0;
    CANCELLED = 1;
    DEADLINE_EXCEEDED = 2;
    INVALID_ARGUMENT = 3;
    NOT_FOUND = 4;
    ENGINE_ERROR = 5;
    INTERNAL = 6;
    UNAVAILABLE = 7;
    RATE_LIMITED = 8;
    QUOTA_EXCEEDED = 9;
    INCOMPATIBLE = 10;
    UNIMPLEMENTED = 11;
    PERMISSION_DENIED = 12;
    UNAUTHENTICATED = 13;
  }
  Code code = 1;
  string message = 2;              // 不含屏幕内容和凭据
  uint32 retry_after_ms = 3;       // 仅用于 RATE_LIMITED
}
```

签名的具体内容按 [安全](11-security.md) 3.3：固定的协议标识串、后台标识、设备标识、挑战随机数，依次拼接后签名。
