## 2 架构

```text
桌面主程序（Electron）：托盘、快捷键、框选、覆盖层、截图浮卡、AI 卡片、服务清单与监管
   │  服务协议：WebSocket + MessagePack，多路复用的流，按条计的流量控制，时限与取消
   ├─ capture          屏幕采集与变化检测（Python，Windows.Graphics.Capture）
   ├─ ocr.rapidocr     OCR（Python，RapidOCR / PP-OCRv6）
   ├─ normalize        归一化：阅读顺序、行与段落、拼接（TS）
   ├─ coordinator      运行协调器：批次、复用、缓存、竞速、请求调度（TS）
   ├─ translate.*      每个翻译源一个进程：claude-cli、openai、anthropic、bergamot、mock（TS）
   ├─ viewer           局域网观看：HTTP、浏览器 WebSocket、画面编码（TS）
   └─ assistant        AI 助手：心跳、门控、AI 大脑、平台工具、MCP 代理（TS）
```

- 每个服务一个进程，按需启动，崩溃后退避重启；服务之间只通过协议通信，任何一个都可以换成别的实现（例如用 Rust 重写 OCR），其他服务不受影响；
- 并发：运行协调器对每个翻译源有独立的并发上限和限速队列，多个翻译源同时竞速；持续屏幕在处理一个批次时，下一帧放进待处理位，不排队堆积；Bergamot 的推理在 worker 线程中，AI 大脑的一轮在独立的子进程中；
- 流量控制：慢的一方（例如解码慢的手机）会让发送方停下，观看服务在对方追上后补发一份最新快照，不会越积越多；
- 平台的窗口（覆盖层、卡片、设置）都排除在屏幕采集之外，AI 截屏也看不到它们。

## 4 关键设计

**竞速与替换。** 默认的两个翻译源是 Claude Code（首选）和 Bergamot。Bergamot 在本机运行、速度快，先给出机翻；Claude 的译文随后逐步替换它，与演示视频中的过程一致。首选源出错或不可用时，Bergamot 的译文成为最终结果。

**持续屏幕的复用。** 每个批次只对变化的区域做 OCR。整体滚动时，按行估计位移，已翻译的段落直接移到新位置；只有新露出的段落送去翻译。滚出又滚回的段落命中译文缓存。

**浮层的绘制方式。** Electron 的透明窗口依赖显卡合成，在远程桌面、虚拟显示器和部分驱动下完全不显示（开发机就是这种情况）。第一版改为离屏渲染页面，再把每一帧推进原生的分层窗口，不依赖显卡，同时保留点击穿透和排除采集。

**AI 助手的分层。** 规则决定"什么时候叫醒 AI"，AI 决定"叫醒之后做什么"。规则门控在本机、零成本，限制叫醒间隔和每小时次数，防止无人看管时持续产生费用；jev 这类快速决策模型可以作为门控接入，没有把握、超时或出错时回到规则。AI 只能使用平台给的工具：截屏、OCR、读译文、画标注、说话；没有鼠标、键盘、文件和命令工具，从结构上保证它不能替用户操作。

**pi 的接入。** pi 作为 AI 大脑在助手服务进程内运行，只启用平台工具（显式白名单，pi 自带的读写文件和命令工具不加载），模型和密钥在设置中配置，也可以接任何兼容 OpenAI 的端点。测试时没有 API 密钥，用一个按脚本回答的兼容端点验证了 pi 调用工具和流式回答的整条路径。

## 5 实测

测试环境：Windows 11，Ryzen 7 8745H，无独立显卡，经远程软件的虚拟显示器（1366×768）。

| 项目 | 结果 |
| --- | --- |
| 整屏 OCR（1366×768） | 约 0.8 秒 |
| 截图翻译，Bergamot 的译文出现 | 请求后约 1.2 至 2.2 秒（含截屏、OCR、归一化；两次实测） |
| 截图翻译，Claude（haiku）的译文替换 | 请求后约 3.6 至 5.3 秒 |
| Bergamot 英译中，4 段 | 110 毫秒（模型已加载）；首次下载并加载约 2 秒、约 53 MB |
| 持续屏幕：测试窗口滚动 3 行 | 复用 22 段，只翻译新露出的 5 段 |
| 持续屏幕：改写一段 | 缓存命中 5 段，新翻译 2 段 |
| 变化图（1080p 滚动） | 约 64 毫秒 |
| AI 助手一轮（Claude haiku，调用 2 个工具并画框） | 约 5 秒；接着追问约 3 秒，记得上一轮的内容 |
| 自动测试 | TypeScript 88 项（含真实浏览器内核中的观看页测试），Python 14 项，全部通过 |

真实桌面上发现并修正的问题（标题并入正文、图标被当作文字翻译、浮层沉到窗口下面、任务栏被压到下面等）记在 [开发记录](dev-log.md)，对应的规则补进了规格说明。之后又由一个独立的测试代理按本文和 README 做了一轮验收，发现的问题（Claude Code 不可用时没有退回 Bergamot、宽窗口里段落合并等）已修正并复测，同样记在开发记录 2026-10-23 一节。

## 6 限制与风险

- **Windows 防火墙**：观看服务第一次在局域网上监听时，系统会询问是否允许；需要用户允许，或者用 `tools/win/allow-viewer.ps1` 只放行观看端口。
- **系统安全提示**：防火墙询问框、UAC 这类系统窗口位于所有置顶窗口之上，画在它们上面的译文和标注会被挡住。
- **OCR 的边界情况**：窗口边缘被截断的半行、复杂的界面布局仍可能分段不理想；规则和阈值的默认值来自实测，需要更多样本调整（验收样本见 [验收与测试](spec/16-acceptance.md)）。
- **未实测的部分**：jev 没有 API 密钥，只用替身测试了门控逻辑；pi 只对接过脚本化的兼容端点，没有接真实的模型服务商；快捷键、拖框和交互模式的点击需要真人在桌面上操作：开发机的桌面前台是一个管理员权限的窗口，Windows 会丢弃模拟输入，所以只验证了快捷键已注册、悬停读的是真实指针；Windows 10 没有测试。
- **OCR 的识别语言**：自带模型识别简体中文、繁体中文、英文和日文；韩文、阿拉伯文等需要另外的识别模型（[使用场景](requirements/08-scenarios.md) 中的模型管理），第一版没有，请求这些语言时 OCR 服务明确拒绝。
- **AI 费用**：Claude Code 和其他 AI 翻译源按调用计费；持续翻译和 AI 助手都有上限和缓存，但长时间无人看管仍会产生费用。
- **Claude Code 无头模式**按需求只用于开发测试和委托方自用；对外分发时应改用 API 接口或 Bergamot。

## 8 运行与验收

运行方法见仓库 [README](../README.md)。建议的验收顺序：

1. 截图翻译：Alt+Shift+S 框选一段英文，先看到机翻，几秒后被 AI 译文替换；
2. 持续翻译：Alt+Shift+C，打开一篇长文并滚动，已翻译的段落跟着移动，新段落随后出现；
3. 手机观看：托盘菜单复制观看链接，在同一网络的手机上打开，画面随电脑刷新；
4. AI 助手：Alt+Shift+A，问"这一页讲了什么，把关键的地方圈出来"。
